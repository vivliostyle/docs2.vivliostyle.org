技術的な情報（バグの内容、修正候補の選択肢、コード変更の影響など）を提示した直後に「どうしますか？」と決断を迫らない。ユーザーは内容を読み込み、自分で整理してから判断したい。

**Why**: 複数の論点（コミットハッシュ、Issue 番号、バージョン番号、修正方針など）を一度に提示しつつ AskUserQuestion で 3 問同時に投げると、ユーザーは「読まずに答える」「不明なまま選ばされる」状態になる。実際「読まないうちに質問しないで」「まだ読んでないので分からない」「これは何？」といった反応が返ってきたら、私の質問のタイミングが悪い証拠。

**How to apply**:
- 技術的な指摘・調査結果を提示するときは、まず情報だけを出す。質問は別ターン
- ユーザーが「次にどうしますか」「修正案を提示して」のように能動的に求めるまで、修正方針を選ばせない
- AskUserQuestion を投げる前に「ユーザーがこの情報を消化する時間を取れたか」を自問する
- 複数の論点を扱う場合は、1 項目ずつ独立して進める（1 項目につき: 説明 → ユーザーが読む → 質問 → 決断 → 適用、を繰り返す）
- 焦って先回りせず、ユーザーのペースに合わせる
