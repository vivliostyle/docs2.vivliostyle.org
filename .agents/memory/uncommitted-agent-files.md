# AI が作成したファイルを未処理のまま残さない

記録日: 2026-11-03

## 確認した事実

2026-10-30 の Codex チャット「上流リポジトリの更新を確認」で、Codex は共有メモリを作成し、「この PR には含めません」「別のローカルメモリとして残します」と説明した。
その後も `git status` に `?? .agents/memory/` が表示されたが、別途コミットする提案をしなかった。
同チャットでは、この未追跡表示を確認した直後に「未コミットの差分がなかった」と報告した箇所もあった。
ユーザーがメモリを恒久的に未追跡とすることを指示した記録は、確認した作成・更新の履歴にはない。

## 原因の分析

「今回の PR に含めない」をファイルの管理方針が確定したことと取り違え、別コミットなどの後続処理を決めなかった。
追跡済みファイルの差分だけで作業の残りを判断し、未追跡ファイルを完了確認の対象から外した。
記憶への書き込みと、その記憶を Git で共有する処理を結び付ける確認手順がなかった。
当時の判断理由そのものは履歴に説明されておらず、内的な動機は断定しない。

## 今後の手順

- 作業開始時と完了報告前に `git status --short --untracked-files=all` を実行し、追跡済み・ステージ済み・未追跡の全ファイルを確認する。`git diff` が空であることだけで未コミット変更なしと報告しない。
- 開始時から存在する変更と、その作業で AI が作成・変更したファイルを区別する。既存の他者の変更を勝手にコミット・削除しない。
- 共有メモリも成果物として扱う。ある PR から外す場合は、別コミットなどの処理先を提案する。「ローカルに残す」だけで完了扱いにしない。
- 自分が作成・変更したファイルは、承諾済みの範囲でコミットするか、対象を明示してコミットの承諾を求める。ユーザーが明示的に保留を指示した場合は、保留対象と理由を報告する。
- 承諾不要のメモリ書き込みは、コミット承諾の例外ではない。追加したメモリも承諾対象の一覧に含める。
- 未処理のファイルを隠す目的で `.gitignore` に追加しない。追跡不要という判断は、内容と共有範囲に基づいてユーザーに説明する。
- コミット後も同じ status を実行し、承諾された対象がコミットされたことと、残る変更の扱いを確認する。

## 今回の処理状況

2026-11-03、ユーザーは、このリポジトリの `AGENTS.md` と記憶5件を現在のブランチにコミットすること、および oboe の `global/AGENTS.md` に全リポジトリ共通の対策を追加して専用ブランチから `main` に反映することを承認した。
push は承認範囲に含まれない。
対策は未追跡ファイルの確認に加え、途中の節目で終了せず、承諾後に実行・検証まで継続する手順も含む。
この記録だけでは他のリポジトリに届かないため、全体指示の正本にも適用する。
