ユーザの GitHub アカウント名義で外部投稿する作業（Issue/PR の起票、コメント、リリース文など）では、内容の客観的事実をすべて**一次情報で独立に確認してから**投稿する。tooling の依存解決や周辺ツールの提示する「最新」を信じない。

これは客観的事実の裏取りに限らない。**自分自身の判断・結論**（設計上の選択、方針の解釈など）を投稿する場合も同様の diligence が要る。「技術的には正しい」だけでは足りず、そのスレッド内で既にユーザや他の参加者が表明した立場と矛盾していないかを、投稿前に読み返して確認する。

**Why:**

Issue #15 の脚注ガイドのスクリーンショット撮影中、`footnote-display: inline` が DPUB-ARIA 脚注で動かない件を Vivliostyle.js Issue #1933 として起票した。実際にはこれは v2.42.0 で対応した機能で、当方は v2.41.0 の Viewer で試していた。最新の `@vivliostyle/viewer@2.42.0` が npm に公開済みであることを `npm view` で確認すれば気付けたはずだったが、`@vivliostyle/cli@10.5.0` が transitive 依存として viewer 2.41.0 を pin しているのを「これが最新」と誤認した。

ユーザから「特別な理由がないかぎり Latest をインストールするのが常識。あなたの回答文は私の署名であり、それを読んだ人が『最新も確認せず Issue 立てるのは雑』と思うのを想像できますか」と指摘された。

第二の事例（docs2.vivliostyle.org #57、生成AIポリシーPR）: `AI_POLICY.ja.md` に本リポジトリ固有の補足節を残す判断を下し、その理由を `gh pr comment` でユーザ名義のPRコメントとして投稿した。だがこの判断は、同じスレッドで村上さんが既に述べていた「本リポジトリを例外にしない」「日本語版はAIが読まないので人間向けの翻訳」という趣旨と矛盾していた。ユーザから「私の名前で間違ったことをコメントをしないでください。以下は削除した」と指摘され、該当コメントは既に削除されていた。事実誤認ではなく、既にスレッド内に表明されていた他者の立場を投稿前に読み返さずに矛盾した結論を公開してしまった点が問題だった。

**How to apply:**

- Issue/PR/コメントを起票する前に、本文に書く客観的事実（バージョン番号、リリース日、URL の到達性、再現環境など）を **一次情報** で独立検証する
  - npm パッケージのバージョン → `npm view <pkg> version`、`npm view <pkg> versions --json`
  - GitHub リリース → `gh api repos/<owner>/<repo>/releases/latest`
  - 機能の対応バージョン → リリースノートや CHANGELOG を直接確認
- transitive 依存に乗ってインストールされた版が「最新」とは限らない。直接依存に追加するか `overrides` で明示する選択肢を必ず検討する
- 起票前に「読み手はこの環境記述をどう解釈するか」を想像する。ユーザの署名で残るので、「最新で試していない雑な報告」と読まれそうなら起票してはならない
- 投稿後でも、間違いに気付いたら追加コメントで明確に訂正する（自分側のミスとして責任の所在を曖昧にしない）
- 議論スレッドで自分の判断を投稿する前に、そのスレッド全体を読み返し、他の参加者(ユーザ本人を含む)が既に表明した立場と矛盾していないか確認する。矛盾に気付かず投稿し、後から気付いて訂正するのは、そもそも読み返せば避けられたミスであり、ユーザの署名で二重に恥をかかせることになる
